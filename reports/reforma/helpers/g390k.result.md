### Attempt 1: answer recording was incomplete

The real updater installed .17, a live new host read the preserved conversation/settings, and all four old app processes exited. A different recorded provider process received resumed input. The continuation assertion then timed out: `run-42158195812.log:1379` records the stack at `scripts/install-update-self.mjs:324:27` (that run's source), thrown by `until` at line 87.

Root cause: the generated provider emitted only final `assistant` and `result` metadata (that run's `scripts/install-update-self.mjs:199-200`). The exact shipped parser accepts main answer text from `stream_event` / `text_delta` (`engine/src/claude.rs:628`); final assistant text is deliberately not added a second time (`engine/src/claude.rs:633`). The corrected fixture emits the missing delta (`scripts/install-update-self.mjs:199`). A no-process VM regression executes the generated provider: it fails against source `6b729299` and passes with the corrected recording. See `g390k/provider-regression-before.log` and `g390k/focused-tests-after.log`. This was a harness failure, not evidence of a new product shutdown failure.

### Attempt 2: the actual post-update announcement covered the conversation

With the complete provider recording, the same conversation **did receive** `Continued after the self-update` from a new provider process, and its state became `ended`. The exact installed package was .17 and all old app PIDs had ended. The stricter visual assertion timed out at `scripts/install-update-self.mjs:331:26`, recorded in `run-42158779408.log:1405`.

Root cause is visible in the retained UI tree, not inferred from a timeout: `run-42158779408/install-update-electron-42158779408/ui-last.json` contains the real `What's new` modal, the `Faber 0.3.19-preview.17` heading, the #707 release note and its `Continue` button. The modal hides the underlying conversation from the accessibility tree. The final harness uses the same actual Continue-button dismissal already used before updating. It does **not** select/reopen a conversation after restart, inject an answer through the API, invoke the target installer, kill old processes or relaunch Electron itself to manufacture a pass.
