## P1: unchecked repair destinations

Git repairs explicit paths and sweeps other registered worktrees. Its linking-file writes truncate existing files.
Before invoking repair, Faber now validates all registered gitfiles and every administrative `gitdir` destination,
including their ancestors, with `real_path` and the existing strict `open_plain_file` handle traversal. This rejects
symbolic links, Windows reparse points and files with more than one hard link. Explicit gitfile suffixes must identify
an administrative directory in the selected repository using Git's literal separator and ASCII-whitespace rules.
The command forces absolute links so repair cannot upgrade relative-worktree configuration.

Native regression evidence, before the production change:

```text
project_paths::t515c_repair_refuses_hardlinked_copy_gitfile ... FAILED
assertion `left == right` failed: repair must not truncate the external copy sentinel
project_paths::t515c_repair_refuses_hardlinked_sibling_gitfile ... FAILED
assertion `left == right` failed: repair must not truncate the external sibling sentinel
test result: FAILED. 2 passed; 3 failed
```

Both sentinels contained the old gitfile bytes; Git changed those external bytes to the moved repository path.
The regression checks sentinel contents before checking the returned error, so an error after destructive writes
cannot pass. `t515c_repair_refuses_hardlinked_admin_backlink` also covers the administrative side of the links.

The first independent security review found a trailing-separator inference bypass in the initial preflight.
It was reproduced with another real repository and a hardlinked foreign backlink before correcting suffix parsing:

```text
project_paths::t515c_repair_refuses_foreign_gitdir_with_trailing_separator ... FAILED
assertion `left == right` failed: foreign gitdir sentinel must stay unchanged
```

The final passing run and independent-review verdicts are recorded below.

The guard additionally refuses embedded NUL bytes and lossy Git path decoding. A Unix-only native test covers form-feed
and nonbreaking-space suffixes; its execution is left to the Unix CI runners. Whitespace handling matches Git's
[character table](https://github.com/git/git/blob/master/ctype.c), and destination coverage follows its
[worktree repair implementation](https://github.com/git/git/blob/master/worktree.c).

## P2: moved selected project is a linked worktree

Repair now supplies the selected project checkout as well as the conversation copy. The integration test creates a
main repository, creates a linked project checkout and a conversation copy, moves the project, invokes Faber's guarded
Git runner, checks its administrative registration, prunes the missing old location, and runs Git successfully in both
remaining checkouts. Unsaved conversation edits are checked byte for byte.

Before the production change:

```text
project_paths::t515c_moved_linked_project_stays_registered_after_prune ... FAILED
called `Result::unwrap()` on an `Err` value: Os { code: 3, kind: NotFound, ... }
```

The failure was at canonicalizing the registration's old, missing project gitfile. The registration was never repaired.

The second independent review caught an introduced edge case: a reclaimed copy can retain its saved record after the
last administration directory disappears. It was reproduced before preserving the existing main-checkout fast path:

```text
project_paths::t515c_moved_project_with_reclaimed_copy_can_be_repointed ... FAILED
called `Result::unwrap()` on an `Err` value: "error.copy.failed"
```

Selected linked checkouts still go through native repair when the conversation copy has been reclaimed.
