# g390s: conditional standing-context cuts

Status: implementation and local verification complete. Four conditional cuts; no model or benchmark calls.

Base: `b0ecb64b2d58f68d2311aafbf3cac58ecd2f674a` (`origin/phase-1-base` at task start), including the conclusion fix from #716 and routing fixes from #717. Worktree and branch: `trim-context`. Prior evidence: `bench-1-0/reports/reforma/helpers/g390t.result.md`.

## Method and limits

The offline Rust matrix covers 120 combinations: both drivers, Chat plain/group, Project owner/member/helper, all six permission modes, and enabled catalog fixtures on/off. It uses the production persona, `thread_params`, `claude_args`, Claude's actual `mcp_tools`, the MCP listing, start-card renderer and delivery methods. A separate in-memory fake-driver regression captures both fresh and resumed Codex prompts. No real CLI or model is called by these tests.

A Project owner has the same standing instructions before and after creating a team: eligibility depends on `started_by`/`goal_fix`, not whether children already exist (`engine/src/engine.rs`, launch). A member is a conversation started by an agent; a helper is the short-lived helper tool, with no lead/progress/card. Chat groups retain the person's words unchanged.

Fixtures use English, default tuning, no custom name or research instruction, fixed `E:/context-fixture` paths, an empty project's 685-character card, and the group instruction `Use metric units.`. Kits=yes means two enabled original fixture skills and one selected body; kits=no means no enabled catalog items. Additional variants cover enabled skills with no selected kit and older plugin support. Arbitrary user text, real project rules/decisions/taste, selected skill bodies and installed integrations vary; these fixture counts are not universal prompt sizes. Native instruction-file discovery is untouched and outside Faber-owned text.

Each cell is **Unicode characters / estimated tokens**. The estimate is the existing offline `scripts/tool-tokens.mjs` score (letter runs per seven characters, digits per three, punctuation individually), not a vendor tokenizer, billing or cache counter. Tool sizes use compact exported JSON, including names/keys/schema framing. Native plugin discovery counts exported name/description metadata; the CLI's own rendering/wrapping is unknown offline. Block sums exclude inter-block separators, resource envelopes, the user's message/history, native CLI prompts/tools and external server schemas. They are inventories, not total model input. Missing native capture is not zero. Existing native histories are not rewritten; savings concern newly assembled blocks, not removal of already cached prefixes.

`g390s-evidence/before.json` and `after.json` contain every row, tool membership and tool sizes. `measure.mjs` verifies that only the specified mode/index blocks shrink and that tool descriptions and schemas remain identical. Raw local logs are ignored to avoid duplicating prompt text in the product commit.

The description itself is 46 characters / 10 estimated tokens; its redundant delimiter adds 2 / 1. Names, jobs, paths, unselected descriptions and the original body remain. A quote containing the same words is insufficient: the whole matching skill body must be present. Missing/different bodies and nonliteral shortened descriptions keep discovery text; Claude's lazy fallback keeps its descriptions.

The mode filter changes only Claude's advertised definitions. `engine/src/engine/settings_change.rs::setting_live` already refuses Plan/Isolated; `creative_judges.rs::creative_call` already refuses Isolated. Call dispatch and those guards are unchanged. Launch permissions remain fixed with the Claude process; the engine replaces the session when its permission mode changes. Allowed modes still advertise both tools. Codex definitions persist with the native thread, so its registrations remain available for a later mode change.

These savings are conditional. **The eight historical benchmark rows were Codex with no selected catalog body: this patch saves 0 characters / 0 estimated tokens in those rows' standing blocks.** It does not explain away the recorded +553,088 cache reads or claim to recover the +148,563 residual after conclusion turns. No realized token saving or live answer-quality result was measured.

## Retained cuts and reasons

- Persona and project rules are preserved byte for byte. The card's rules, permissions, approved decisions/taste and validation are useful even for small tasks; the Chat boundary already excludes Project details, bigger offer, lead text and cards. No request-content classifier or relevance guess was added.
- The 2144-character / 502-token lead contract is usable without an existing team because the owner can create one. It is already absent from Chat, team members and helpers. Removing it based on an empty team would remove the instructions needed to form that team.
- The 203-character / 44-token bigger offer is independent of team creation. Its tool remains usable by a Project conversation, including a team member. Its overlap with the tool description is not an exact duplicate: the standing instruction also forbids asking another way. The once-offered/away cases were not turned into mutable per-turn prompt/tool changes.
- The 503-character / 140-token guide index is already lazy. Follow-up questions may need it, and session prompts stay stable. Plugin sessions already avoid the index. The inline fallback is retained when writing the guide folder fails; omitting it would lose help and frontend instructions. Its language-specific sizes are measured below.
- Native Claude skill descriptions are not injected body text. Codex's unselected skill descriptions, oversized skills and path/job metadata remain discoverable; selected bodies and catalog/native integrations are not removed. A catalog tool with a currently refused write action still has usable offline search, so its whole schema is retained.
- Codex's browser/verifier/map and other registered definitions may be refused in the current mode but become usable after a mode change on the same thread. Removing them at initial registration would lose that later capability. The current live-mode guards are retained. If the shell/provider is absent, the existing engine capability flags omit those tools already; helper export also depends on the other CLI being configured.
- No shortening of validators, evidence, independent-review instructions, tool schemas, safety/accessibility rules, user skills, project files, or research availability. No semantic near-duplicate cut was made where information or instruction priority might change.
