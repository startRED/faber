## Current product bugs exposed by W5, deliberately not fixed

The real W5 suite was temporarily materialized at `scripts/t515j-w5-comparison.test.mjs` and run with
`node --test scripts/t515j-w5-comparison.test.mjs`, then removed. Its original source remains available through
`git show origin/w5-dl-electron:scripts/electron-sidecar.test.mjs`.
`E:/Temp/faber-t515j/w5-direct-comparison.log` records 9 tests: 5 passed, 4 failed.
Independently written temporary probes reproduced the same four failures; their source and output are preserved
outside the worktree as `current-bugs.probe.mjs` and `current-bugs-red.log`. No failing probe is part of the PR.

1. **A: repeated Quit can bypass an unfinished save.** `electron/main.ts`'s `before-quit` handler returns immediately
   when `stopping` is already true, without preventing the second event's default. Repro: keep `host.stop()` pending
   and emit two `before-quit` events. Only one is prevented, while both must be held. The independent probe observed
   `{ prevented: 1, stops: 1, quits: 0 }`, expected `{ prevented: 2, stops: 1, quits: 0 }`. The second Quit can let the
   shell exit while the engine is still saving.
2. **B: failed shutdown removes the tray and cannot retry.** The same handler calls `release()` before shutdown
   completes and uses `.finally(() => app.quit())` even on rejection. Repro: reject an injected `host.stop()` promise
   and emit Quit again. The independent probe observed `{ stops: 1, quits: 1, releases: 1 }`, expected
   `{ stops: 2, quits: 0, releases: 0 }`. The rejection cannot preserve the usable shell or start another stop attempt.
3. **C: a denied kill leaves shutdown waiting indefinitely.** `electron/sidecar.ts::stop` ignores `child.kill()`'s
   false return and awaits `this.exited` with no rejection or retry path. Repro: let the minute timer expire, return
   false from the mock kill and withhold exit. W5 and the independent probe both report `Missing expected rejection`;
   the stop promise remains pending. Cleanup in the probe supplies exit explicitly afterward.
4. **D: a process error is mistaken for exit.** `electron/sidecar.ts::launch` calls `gone()` for every child `error`,
   including errors after a process successfully spawned. Repro: use a mock child with a PID, begin stop, then emit
   `error` without exit. Both suites observe stop complete (`true`) when it must still be pending (`false`). This can
   let the shell leave while the engine still exists. Genuine spawn failure without a PID is a separate case that
   W5 verifies successfully.

These are findings against the combined #675/#676 product, not regressions introduced by this test commit.
No shipping-code fix was made silently.
