## Blocker 1: empty hydration silently skips an unimported legacy draft

Regression: `failed import followed by an untouched empty composer recovers the legacy draft after restart` (`electron/migration.test.mjs`).

The integration proof seeds synthetic legacy Chromium localStorage/IndexedDB in a separate process, injects attachment-marker failure to roll back `new-chat-`, mounts the real Solid Composer without typing, exits, and retries import in a separate Electron process. Every BrowserWindow has `show: false`; the production importer uses unattached sandboxed views. The original profile remains untouched.

Before product edits, `blockers-red.log`:

```text
PASS: failed import followed by untouched composer mount
AssertionError: Tauri draft must reach the new origin
actual: null
expected: 'my unsent draft'
```

Fix: `ui/unsent.ts` distinguishes an initial empty write from new text or consumption of an existing/failed draft. Only the latter resolves per-field legacy import progress. A failed earlier write in the memory map still counts as use, including a pending failed deletion; explicit full draft deletion retains its existing attachment/progress path. No new edit registry or API option was added.

After, `blockers-green.log` and final `electron-all.log`:

```text
PASS: failed import followed by untouched composer mount
PASS: legacy text, binary attachments, conflict and deletion preservation, idempotence
PASS: failed import followed by screen writes and consumption, including an unreached field
PASS: retry preserves consumed failed and unreached fields
```

The earlier `failed import never restores a field used and consumed by the screen, including unreached fields` regression remains passing: new text then consumption, attachment-only use and consumption, failed progress writes/deletions, and untouched legacy fields are all checked. Existing quota rollback, completed-field consumption and binary-byte/MIME checks remain intact.

Two initial harness runs had bundle-return-shape and browser-context/clone errors. These were corrected before product edits; they are not counted as product failure evidence. The retained red log above reaches the actual draft-loss assertion.

## Blocker 2: automatic host recovery destroys a failed-write draft

Regressions:

- `engine restart forwards recovery to the live renderer instead of destroying its unsaved draft` (`electron/recovery.test.mjs`) executes the real main-process event callback with a controlled renderer boundary.
- `engine recovery refreshes state while preserving a live composer whose draft write failed` (`electron/migration.test.mjs`) mounts the real App and Composer in hidden Electron, injects localStorage failure, delivers recovery, and verifies the same textarea node, newer text, in-memory draft and dirty protection survive. It also checks fresh state, restarted running-list revisions, refreshed quota readings and precedence of a newer quota event over a delayed snapshot.
- Existing `a crashed engine restarts, refreshes the screen and never replays requests` (`electron/sidecar.test.mjs`) exercises the actual Sidecar with controlled child streams and timers; it continues passing.

Before product edits, `blockers-red.log`:

```text
AssertionError: recovery must not destroy the renderer heap
actual: 'old durable text'
expected: 'newer text whose storage write failed'

Error: replacement engine state must refresh without reloading
```

Fix: `electron/main.ts` forwards `lagged` through the existing event channel instead of unconditionally reloading the renderer. `ui/App.tsx` refreshes state, the open conversation and pending asks in place, resets process-local running/background revisions, and preserves the mounted Composer and shared failed-write memory. Recovery snapshots refresh quota readings without replacing later quota events. Pending requests are still rejected and never replayed.

Fresh review found that retaining the renderer also requires reannouncing its dirty state to the replacement updater. Expanded negative control, `dirty-reannounce-red.log`:

```text
Error: replacement updater must learn about the retained unsaved draft
```

The recovery handler now sends `draftDirty(dirtyCount() > 0)` to the replacement host. The hidden proof resets the fake host's guard on restart and requires it to be restored even while persistence continues failing. This prevents loss of updater protection when the renderer's dirty boolean has not changed.

After, `recovery-expanded-green.log` and final `electron-all.log`:

```text
PASS: engine recovery retains newer unsaved words and refreshes state
```

The main routing, live screen and Sidecar lifecycle regressions all pass. The process protocol, main routing and real browser screen are tested at controlled boundaries; no real engine binary was killed.
