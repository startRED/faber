## Fix

`Core::after_route` used the same reason for the route's difficulty and its displayed fallback explanation. Immediate sends replaced `reason.route.*.easy` with `reason.autoImmediate`; temporarily having one usable profile replaced it with `reason.autoSingleProfile`. `next_route` then permanently declined later drafts.

The fix keeps an existing `reason.route.*` on the stored/dispatched pick and `Message.reason`, while the resolved display pick and route act retain the immediate/single-profile explanation. The model-header tooltip still describes the stored route; the Faber act explains this send. No new persisted field, migration, dependency, process or resident state is introduced. The timeout explanation still distinguishes the single-profile case using the display pick. Both direct and queued sends already share this function; quota admission and no-downgrade checks are unchanged.
