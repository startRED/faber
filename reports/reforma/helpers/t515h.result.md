## P1: interrupted attachment publication was finalized by text hydration

Regressions in `electron/migration.test.mjs`:

- `crash before attachment publication followed by a read failure and untouched composer recovers attachments on restart`.
- `hydrating pending import text never completes its attachment publication`.

The hidden proof runs separate Electron processes against synthetic browser profiles. It intercepts only the attachment-marker instruction in the real importer script: after the IndexedDB transaction completes and text is written, execution suspends and the Electron process exits without executing rollback. The next process verifies durable `pending` progress, surviving text and an absent attachment marker. A temporary legacy-storage read failure aborts import; the real Solid Composer then mounts without typing. A final process retries import and checks the original image bytes/MIME, file bytes and inline metadata, plus conflict/deletion preservation and idempotence. Every BrowserWindow has `show: false`; the production importer uses unattached sandboxed views.

Before product edits, `regressions-red.log` reached the exact reported loss after the untouched mount and restart:

```text
PASS: interrupted import before attachment marker publication
PASS: failed-read-idle with untouched real composer
AssertionError: null !== '1'
```

The missing value was `faber.unsent-attachments.new-chat-`. The independent pending-hydration check also failed:

```text
AssertionError: hydration must not finalize a pending import
'1' !== 'pending'
```

Fix: `electron/migrate.ts` reconciles pending publications at the destination before reading legacy storage or checking global completion. It removes the incomplete text, attachment marker and per-field progress so a temporary legacy read failure cannot expose half a draft. It retains the old profile and committed attachment bytes for the next retry. `ui/unsent.ts` hides pending imported text and refuses to resolve pending publication through screen text or attachment writes; existing memory, dirty and attachment-error handling receives the failure. No new registry or API option was added.

After, `electron-green.log`:

```text

PASS: failed-read-idle with untouched real composer
PASS: legacy text, binary attachments, conflict and deletion preservation, idempotence
PASS: hydrate-pending with untouched real composer
```

The expanded proof also requires an empty mounted textarea, startup rollback before the failed legacy read, and refusal of a direct screen write while progress is still pending. Earlier failed/consumed and unreached-field import regressions, attachment-marker quota rollback, empty Composer retry, live failed-write recovery and host backoff all remain passing.
