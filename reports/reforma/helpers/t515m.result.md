## Root causes

1. **Rust product-map cross-check: global storage deduplication, not a missing product-map row.**
   `map::scan` deliberately lists each stored key once, at its first source file. Those entries are attributed to `electron/`, which sorts before `ui/`. The product-map test incorrectly restricted discovered keys to `ui/`, then compared them to all UI keys. Existing product-map rows already document the affected storage. The fix checks that every UI key exists in the complete deduplicated index, without changing index ownership or weakening the separate map-document completeness check.

   Local pre-fix reproduction through `node scripts/cargo.mjs t --filter the_project_map_read_from_faber_s_code_finds_what_the_product_map_is_checked_against` produced the same panic at `engine/tests/product_map.rs:202` and the same seven-versus-twelve key sets (`rust-red.log`).
