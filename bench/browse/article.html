Configuration

Part 1

Section 1 explains one part of the tool in detail. The configuration lives in a single file at the root of the project, and every option has a default that works for most teams. Changing an option takes effect the next time the tool starts; nothing needs to be rebuilt. When two options disagree, the more specific one wins, and the tool prints which rule it used so the choice can be traced later on.

For example, setting retries to 3 makes a failed request run up to three more times, waiting a little longer between each try. The wait grows by a factor you can set with backoff. Both values must be whole numbers; anything else is reported at start-up with the line it came from.
