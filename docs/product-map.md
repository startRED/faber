# Product map

What Faber has today, for whoever builds the next part. [product-rules.md](product-rules.md) says where a new thing goes;
this page says what is already there, so a new part extends it instead of adding a second way to do the same thing. How
each part looks and moves is in [design/](design/README.md); where Faber is going is in [product/](product/README.md).

The map names files and keys, never line numbers. `engine/tests/product_map.rs` fails when a setting, a `ui/*.tsx` file,
a shell command or a browser storage key is missing from it; words, flows and features stay true because the commit
that changes them updates this page too. Last full audit: 2026-10-16.

## Every setting

`settings.json` in the data folder holds the struct `Settings` of `engine/src/model.rs`; `ui/api.ts` mirrors it by hand.
The `save_settings` command (loading old `verbosity` rewrites it once as `replyStyle`: low to short, high to explained, medium/default to default, then drops the old key; an existing new choice wins) and plan approval share `Core::save_settings` (`engine/src/engine.rs`), whose merge builds a
full `Settings`, so a new field does not compile until it is merged. A patch sets a value and never clears one (an empty
`userName` is the only way back to none). Rust readers read the file when they need it. The screen takes the saved

## Other stored state

The data folder is `%APPDATA%\Faber` (or `FABER_DATA_DIR`). On Windows, setup and engine construction open its directory chain without following existing links before crash bookkeeping, settings, Store, catalog tasks or orphan cleanup. Crash-hook installation validates the same directory before replacing the global handler; refusal exits without a panic writer. An invalid path returns a startup error; the engine keeps the opened directory handles until its other fields are dropped (`workspace::DataDirectory`, `engine_startup_*` in `engine/tests/engine.rs`). This entry check does not establish protection against concurrent reparse changes, a data-write sandbox or external Chat migration; other hosts retain ordinary directory creation. JSON files are written through a temporary file and renamed. Message search keeps no file: its sorted, deduplicated words live in one newline-delimited string per conversation, with no message text or positions; it builds at background priority and follows successful conversation saves and removals. Candidates are read newest first off the engine lock to find the first message matching every query prefix, up to 30 conversation hits (`engine/src/search.rs`, `engine/src/store.rs`).

unfinished batch is reclaimed at startup or sealing. Derived indexes are not needed to read saved versions. Cleanup uses

## Shell commands

`background_commands` reads the ephemeral command list and its revision; `stop_background` takes only that list's opaque row id,
validates a still-running stoppable command and routes its native task id to the session that started it, including a retired
session. A five-second acknowledgement deadline reports a failure for retry; only the CLI's completion ends the row.

Rewind uses `rewind_points` (conversation points and coverage), `rewind_preview` (file/message counts,
conflicts, running writers and recovery), `rewind_restore` (files, conversation or both, with per-file conflict choices),
`rewind_redos` (available redo journals), `rewind_redo_preview`, `rewind_redo` (saved versions and messages without running commands),
and `rewind_recover` (finish interrupted recovery). A missing working folder leaves its journal pending and returns
`error.rewind.recovery`, allowing retry when that same folder returns. A redo stays discoverable as recovery until the
caller durably saves the conversation and acknowledges its journal; then it cannot be offered or applied again.
Deletion is refused with `error.rewind.deleteRecovery` while that conversation has a pending recovery journal,
including deletion with `discard`. The existing error display asks the person to finish the interrupted restore first.
An ordinary capture, seal or admission does not refuse deletion: it waits outside the engine lock, rechecks recovery
and preserves the copy's unsaved-work question (`rewind_deletion_waits_for_capture_without_holding_the_engine_or_losing_the_unsaved_check`).
Their types and calls live in `ui/api.ts` and the confirmation in
`ui/Rewind.tsx`. Errors use `error.rewind.*` keys. Restore kills no work:
overlapping conversations, helpers and checks must be confirmed idle, and admission stays closed during restore/recovery.
Writer snapshots remain scoped to each session across model/effort changes; retired owners retain their Stop route and
late tracking events until exit is confirmed. A replacement session's empty snapshot cannot clear earlier running work.
Session ownership is registered before launch or delivery. Deletion, archive, queued idle snapshots and replacement
cannot discard that admission before confirmed termination. Faber-owned commands, Stop and session close share one container proof:
Windows queries the owned job's active-process count; Unix requires the owned process group to report no member.
Closed output pipes or an ended main process alone never release unknown writers.
At each turn's end the owned container is inspected for processes other than the CLI itself, regardless of tool events;
hooks and other unannounced children remain unknown until gone. Idle Stop ends and confirms that session's tree when
no peer is using it and no reported terminal still needs CLI confirmation. Reported command/terminal identifiers are opaque
protocol handles, never operating-system process IDs; they authorize no native claim or kill. Stop sends the CLI's own
scoped termination request for that conversation's reported handles, then checks its complete terminal listing; a peer's turn is preserved.
Windows keeps its owned job-object proof. On Unix, neither an exit code nor a missing terminal in the CLI listing
releases a native writer by itself. Faber samples the shared app-server's descendants by parent chain when a command is
reported and before release, retaining sampled identities across parent exit. While any live descendant remains outside
the original group, every conversation on that server keeps sealing and restore blocked, including after disconnection.
On macOS, descendant sampling walks only the owned tree and remembered orphans, includes zombie parents for ancestry,
and treats a reaped group member as gone; unrelated system processes need no inspection permission.
The Unix regression `rewind_a_native_exit_keeps_every_shared_conversation_blocked_until_its_sampled_child_exits` covers a successful
command exit with a surviving barrier-held child. Unattributed work or failed confirmation
keeps restore blocked, with the conversation, Background work and a plain explanation in all five languages.
Real contained-process checks live in `engine/tests/codex_session.rs` and `engine/tests/claude_session.rs`; the translated
unconfirmed-Stop state is checked in `tests/ui/rewind.check.ts`.
An unavailable project folder makes actual work unknown; an idle loaded conversation from a removed project does not
become a writer. Normal session closure retains tracking through confirmed shutdown before publishing idle.
Deleting a conversation retains its folder and existing work trackers until session writers, helpers, checks and
admission finish; deleted conversations do not reappear. Retained folders participate in overlap and sealing revision checks.

## Features and their checks

Chat groups extend the Chat sidebar with expandable project-style rows and nested chats; outside chats retain their date and pin lists. Groups are reconciled synchronously by id so their row, rename draft and focus survive refresh, including a changed name saved with Enter; Escape from rename returns focus to the group row. A refreshed list clears a deleted group selection from the screen and browser storage before New conversation or Ctrl+N. Keyboard Move to group restores focus when the destination row exists, unless the person moved focus meanwhile (`chat groups: deleting`, `chat groups: keyboard Move to group`). Knowledge files use the existing attachments and images, never CLI configuration files: JPEG, PNG, GIF and WebP are images, SVG is text, BMP and AVIF are refused. ## Worked example: adding a setting

Say people want to turn off the cache-warm note.

1. Check the map first: no setting covers it, and it is a preference for every conversation, so it is a field of
   `Settings`, not of a conversation, a project or browser storage.
2. Add `cache_note: Option<bool>` to `Settings` in `engine/src/model.rs`. The merge in `Core::save_settings` and
   `engine/tests/product_map.rs` stop compiling until the field is in both.
3. Give it one default in one place and read it there.
4. Mirror it in `Settings` in `ui/api.ts`.
5. Place its control with [product-rules.md](product-rules.md): a `Toggle` from `ui/controls.tsx` in the Settings section
   it belongs to (General), one short line, never on the conversation screen.
6. Write its label and hint in all five `ui/locales/` files by hand.
7. Extend `tests/ui/settings.check.ts` (and `testkit/src/screen/settings.rs` when it changes the real app).
8. Add its row to "Every setting" above, in the same commit.

What not to do: a second control for something that already has one, like a model select under every answer next to the
composer's model picker (R168 removed it). That is the mistake this page exists to prevent.

Unfinished agent calls loaded without a live CLI, or copied into a new conversation, retain an optional `ToolUse.interrupted` marker. The existing Subagent step and background-work projection show them stopped and exclude them from the live-helper count, even under a completed reply; known results, briefs and history are preserved without replay or an invented end time (`engine/src/engine.rs`, `settling_a_reply_interrupts_unfinished_agents_without_inventing_results`; `tests/ui/agents.check.ts`, restarted agents).
