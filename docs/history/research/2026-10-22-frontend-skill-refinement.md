# Frontend skill refinement

Status: paired generation, blind review and independent instruction review complete; integration in progress.

## Why this refinement exists

The first bakery pair tied at 17/20. Its treatment consulted only part of the installed art-direction instructions,
so it could not isolate the value of the new first-party skills. Independent critique also found task context below
a tall mobile introduction. The author's successful instant mode had not exercised the actual eight-second wait;
a separate root runtime follow-up closed that gap without changing the frozen scores or either sample.

These are reasons to clarify the workflow, not proof that a checklist improves taste. The original first-party skill
remains the interaction/proof layer; it complements an applicable installed art-direction workflow for new identity,
while local repairs retain the existing direction. The first useful viewport should reveal the actual task and
essential context. This is conditional guidance, not a universal hero ban. Verification now explicitly exercises
slow completion; a separate instant-success mode is insufficient.

## Planned comparison and controls

Old skill bodies were snapshotted before editing in the ignored local evaluation workspace. Two fresh generation
sessions receive the same exact brief, native single-file constraints, complete same installed art-direction
instructions and inherited model configuration. The exact runtime model variant is not exposed/pinned. Only the
first-party skill bodies are intentionally changed; model randomness, author choices and reference interpretation
remain uncontrolled. One sample per condition cannot establish causal/statistical superiority or overall mastery.

## Integration follow-up

The queued instruction change exposed one existing UI failure: 702 checks passed and the confirmed draft-deletion
check read a remaining `forget` marker after a fixed 40 ms delay. A local real-IndexedDB characterization defers its
success callback by 80 ms; it reproduced the same expected-null/actual-forget failure (two focused checks passed,
one failed). The updated check waits for both durable markers to clear, with a bounded two-second safety wait, and
retains the existing assertions on words, markers, refusal and the actual retry control. The adjacent single-draft
retry uses the same completion wait. No product state machine or storage implementation changes for this repair.
The slowed open still exercises real IndexedDB requests and transactions. The first final run passed all three affected
checks, including the two-draft case at 358 ms, but failed its separate cleanup audit: a synthetic-profile NVIDIA
DXCache file remained after the app tree exited. No retained cache was removed or cleanup failure waived. A fresh
ordinary run then exited zero: three focused checks passed, no failures or skips, and its cleanup audit passed
(386.9 s total including shared-slot admission; 5.1 s build, 155.4 s UI). The two-draft case completed at 338 ms.
The first cleanup failure remains a separate failure; its cause was not established or repaired by the test change.

Separate negative-control work found that copying restored source files with old timestamps could leave Cargo using
an earlier executable. Source checksum equality did not prove the executed artifact's identity. A final three-line
proof addition now requires checking the executable or served bundle after changing/restoring sources and invalidating
stale artifacts through the build system. This changed the proof file from 7,466 to 7,805 bytes after the frozen pair;
the generated-page scores do not measure it. A fresh read-only instruction/test review found no blocker; final
integration remains separate.

A later consolidated follow-up adds a list-identity check after a separately reproduced paging/focus regression.
It adds 301 bytes to the craft file (9,503; proof remains 7,805), keeping discovery descriptions unchanged. This is
an instruction addition, not another generated-page experiment; the frozen scores do not measure its effect.
