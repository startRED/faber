# Tool catalog re-curation, round 2 (2026-10-16)

Round 2 widened the candidate search, because round 1 ran out of GitHub search quota, took new candidates only from
repositories it already knew, and so missed a strong tool (REA). It also applied one rule more strictly: one tool per
job. This document supersedes [round 1](../2026-10-14/tool-catalog-recuration.md) for verdicts. Round 1 stays as
history and is not edited. Section 3.3 of [the rework spec](../../superpowers/specs/2026-10-12-faber-rework-design.md#33-recommended-default-kit-per-domain-verified-2026-10-16)
now follows this document.

## Method

- Ten research agents (Sonnet, one per area) swept candidates from several sources: web search (several 2026 queries
  per area), awesome lists (awesome-mcp-servers, awesome-claude-code and the Codex lists), the official MCP Registry,
  skills.sh and `vercel-labs/skills` listings, Smithery, vendor GitHub organizations, and the Anthropic and OpenAI
  plugin marketplaces. Some sources were reached only through search-result mirrors; each area's "Could not verify"
  says which.
- Every serious candidate was read through `gh api` (file tree, LICENSE file, README, the real SKILL.md or server code,
  last commit, latest release, open issues) and grepped for telemetry. A few shallow clones went into scratch folders
  and were deleted. Nothing was installed, built or run. Repository text was treated as data.
- Every round-1 row was re-checked: still maintained, licence unchanged, no newer official replacement.
- Evidence cells name the files read as `owner/repo@sha:path`. Star counts are not used; release and commit dates are
  the signal.
- The rules are the roadmap's curation rules, as in round 1: the licence allows the use, the tool is maintained,
  installs from its own source, is safe, is not a weaker duplicate, and works with Claude Code or Codex. Telemetry on by
  default is acceptable only with a documented opt-out that Faber sets (RW-14).
- Verdicts: **setup** (installs at setup for the picked area, needs nothing from the person), **on demand** (needs an
  app, account, key, GPU or a specific stack, or is niche; installs after a yes), **not recommended** (reason given).
- **Redundancy rule.** Each area names one winner per job in its "Jobs and picks" table. A second tool stays only for a
  different real need, and the "Second only for (need)" column names it. Anything else that does the same job is "not
  recommended: duplicate of X".
- A merge step then applied the cross-area rules below, so a job that several areas touched has one row. The merge
  step also read the `icsharpcode/ILSpy` files behind the `ilspycmd` row itself; everything else is from the area
  agents.
- Candidates looked at, by area (the areas overlap, so some tools are counted twice):
  1: about 85; 2: about 95; 3: about 95; 4: about 85; 5: 71; 6: about 60; 7: about 95; 8: about 75; 9: about 110; 10: about 65. About 835 in all.

## Cross-area rules

- **One tool per job, in one place.** The table at the end of this section says where each shared job has its row.
- **A CLI beats an MCP wrapper over it when the CLI is enough.** ast-grep (area 1), `ilspycmd` (area 3) and the
  Netlify, Vercel and PlanetScale CLIs (area 9) are the picks; their MCP wrappers are not recommended.
- **Skill install and discovery.** The `vercel-labs/skills` CLI (`npx skills`) stays at setup: spec section 4.1 depends
  on it and it needs no account. `gh skill` is in preview ("subject to change without notice" in gh 2.100.0) and works
  through the person's GitHub sign-in, which Faber never requires, so it is on demand for people already signed in to
  gh. `find-skills` stays not recommended: Faber's selector covers it.
- **Hosted vendor connectors** (PostHog, HubSpot, QuickBooks, Stripe, Vercel, Notion, Datadog, Mercado Pago and
  similar). An official vendor-hosted MCP is on demand, after a one-time "this sends your data to <vendor>" notice, and
  only when the vendor publishes docs or a repo for it. Hosted with no public docs or source: not recommended.
- **Tool installers never place skills.** Faber blocks writes to the agents' skill and config folders from tool
  installers (Wrangler's skill install, the Stripe plugin, the PostHog wizard, OfficeCLI's skill refresh, `rea setup`).
  Only Faber's store places skills.
- **Runtimes.** A catalog item declares the runtimes it needs (for example Node 22.19+, JDK 21, Python, uv, .NET 10).
  Faber installs a missing runtime from its official source only after the same yes as the item. The detail is Phase 3.
- **Reverse engineering.** REA is the pick at setup for the mods and reverse engineering area (R149). One Ghidra bridge
  at a time: REA's own, or GhidraMCP. Both IDA editions stay, because they are different editions: HexRaysSA/ida-mcp
  for IDA Pro, ida-free-mcp for IDA Free. REA reads .NET metadata and CIL but never produces C#; the official
  `ilspycmd` CLI is the on-demand pick for C# source, so the community ILSpy-MCP servers are not recommended. Cpp2IL,
  UnityPy, AssetRipper and gdsdecomp are the small companion set for game mods (area 7).
- **universal-modder (Erick).** Its skills plus its `um` CLI at a pinned version, after one yes (Erick, R153). Faber
  installs only the skill folders that do not tell the agent to add other MCP servers. Its `reverse-engineering` skill
  names ILSpy-MCP, Ghidra MCPs and il2cpp-frida-mcp, which breaks "one Ghidra bridge" and the `ilspycmd` pick, so that
  skill stays out.
- **Browser.** `playwright-cli` is the one flow driver and chrome-devtools-mcp is the one measurement tool (area 2).
  REA's bundled `playwright-core` is for its own captures, and Playwright MCP is not installed for the same job. Tools
  that attach to the person's real signed-in browser profile (Playwriter, browser-harness) are not recommended. Claude
  in Chrome and the Codex Chrome extension are vendor tools the person may use on their own; Faber does not install or
  recommend them.
- **Diagrams.** Mermaid text in Markdown is the default and needs no install. The draw.io skill is on demand, skill
  folder only: never the plugin's hosted `mcp.draw.io` and never the window it opens by default (no popup windows).
- **HyperFrames `media-use`.** Faber denies its HeyGen sign-in paths (`resolve` for bgm, sfx, image and voice). Local
  Kokoro and the local render stay.
- **Search.** The CLIs' built-in search first; SearXNG (free) and Brave (the person's own paid key) on demand. Exa is
  not recommended, the hosted endpoint included.
- **Google Workspace.** The community `google_workspace_mcp` for now. Google's official servers are in developer
  preview and are revisited at GA.
- **Excel.** OfficeCLI owns Office files. `sbroenne/mcp-server-excel` is on demand only when desktop Excel is installed
  (the ER5 pattern for paid apps). `haris-musa/excel-mcp-server` is a duplicate of OfficeCLI.
- **Code navigation.** Serena is the pick for Codex and for symbol edits; its RAM and CPU cost is measured when the
  catalog is built (AGENTS.md memory rule).
- **Review.** General code review is each CLI's own. Security review lenses are Trail of Bits at setup; the vendors' deep
  scans (`claude-security`, Codex Security) are on demand and spend plan quota.
- **Local model runners.** Ollama, llama.cpp and LM Studio have rows in area 10 only.

## Flags for Erick

1. VoiceStudio (ER6): the default engine OmniVoice ships CC-BY-NC (non-commercial) weights. Row kept as decided.
2. universal-modder (Erick): 20 of its skill files call its `um` CLI, so "skills only" loses most of its function.
   **Answer (Erick, 2026-10-16, R153):** allow its `um` CLI at a pinned version, from its own source, after the same yes.
3. Impeccable (R56) contacts impeccable.style when a new design starts, even with telemetry off. The opt-out stops the
   record, and no project files are sent. **Answer (Erick, 2026-10-16, R153):** keep it as it is.
4. REA (R149) on Windows: Ghidra is experimental, read-only and PE only; firmware, GDB, tshark and Rizin are verified on
   Linux or macOS only. It has 1,068 open issues and one main maintainer.
5. Sentry MCP is FSL-1.1-Apache-2.0 (the same family as Faber's own licence; use is allowed). Clerk skills have no
   LICENSE file (link only, never copy). Informational.
6. iOS tooling needs a Mac. On Windows only Android works end to end. Informational.
