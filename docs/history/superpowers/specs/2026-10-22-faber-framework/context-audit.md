## Current truth before planning

The first working copy was older than the shared product. Revision 2 corrected the retired-missions assumption.
Revision 3 additionally inspected current shared product and frontend documents rather than treating this copy's
file inventory as complete. Live source/decision records outrank dated specs about current runtime behavior.

Every implementation packet must identify the actual working root, relevant source revision, input versions,
adopted decision references and tool availability. Refresh when those inputs change; do not load the entire project.
Hashes identify inputs; they do not grant permission, establish content safety or replace private owner authority.

There are three separate states to communicate:

- **Built:** observable behavior has current program evidence for the relevant build and environment.
- **Approved:** an authorized product choice; it may still have no implementation.
- **Proposed:** this research's candidate, needing normal review/adoption and then implementation proof.

The R435 document's historical implementation label and evolving code can differ. Confirm each slice from current
code and evidence before assigning work; do not declare all four slices either finished or untouched from a header.
The existing frontend instructions are built delivery, while generated-result quality still needs comparisons.

The older Academy study lives at docs/research/2026-10-13/claude-academy.md in the shared project. Its model/pricing
figures and historical integration statements are dated observations, not product constants. Current source and
measured CLI behavior decide effort, discovery and cache policy; API-only tricks are not subscription features.
