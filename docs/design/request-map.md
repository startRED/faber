# Request map (R589)

Below the newest answer, the request map counts working, current, redone and missing parts. It stays visible on reopening,
including when all parts work or the plan has no technical steps. Technical details holds the agent's steps.
The area where work is under way opens first. A single area needs no strip. With more than six areas, a single pile
holds the completed areas and any overflow. Select an area to open its panel.

Up to five blocks show the working pile, the latest working part, current work, the next missing part and how many
remain. When two parts are under way, the working pile makes room for them. See all reveals folded and removed parts.
Working parts have a solid green edge. Current work and redone parts have a dashed amber edge, and missing parts a
dashed neutral edge. Examples and reasons hang below their block. See proof shows the evidence and newest saved
picture.

Narrow layouts stack the blocks and show two areas per row. During a reply, the live line shows how long the current
part has been under way and when the most recent part started working. The timer stops when hidden, and the gentle
pulse follows the person's motion preference.

## Map capture comparison

The comparison opens from a map block with two distinct browser captures. It starts with the explicit before capture, or
the first capture, and the newest capture after it. A single call's screen sizes count as one capture. Portrait pictures
without size information use the phone layout. Phone captures use two frames side by side. Wide captures share a divider
that moves with the pointer or keyboard. Choose Phone or Computer when saved variants let you switch.

The strip opens each capture in order, shows its time when available and marks the newest. The note below repeats what
the person asked for. The close button and Escape both return focus to the map. The comparison requests pictures only
while it is open.
