# B6: Tray Number and Notifications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The tray icon shows an amber number while agents wait for the user, its tooltip says the same in words, and Faber sends one notification per question, only while the window is unfocused or closed.

**Architecture:** What to show and when to notify is decided by plain functions that know nothing about Tauri: `tray/decide.rs` (the words, the counts, "is this question new") and `tray/badge.rs` (the pixels of the number). `tray.rs` hands their answers to Tauri (the icon, the tooltip, the menu, the notification). The engine's `Running` events reach the tray on a thread of their own, so the engine's lock and the main thread never wait for each other, and the tray keeps only the newest revision. The screen sends the shell its words (`set_shell_texts`) whenever the language changes.

**Tech Stack:** Rust 2024 (Tauri 2 with the `image-png` feature, `tauri-plugin-notification`), SolidJS + TypeScript, the Rust test runner `cargo t` (suites `rust`, `ui`, `screen`).

**Spec:** `docs/superpowers/specs/2026-10-11-faber-redesign-design.md`: B6 (all of it), B0 (commit 8, "B6: tray and notifications"), A7 (the "Tray" paragraph), AI-18, Review log round 2 item 26, B4 ("If a tray PNG fails to decode"), B12 items 7, 8 and 10. This is commit 8 of the order in B0. It uses B5a's `Running` event and must not depend on B5b's screen code.

## Review Focus

Failure modes the spec implies and a person would meet, most likely first. Each one has a test in the task named after it.

1. **Two agents ask at once with the same request id** (Codex numbers its requests from 0 in each server, so two conversations, or one conversation in two turns, can both hold request `0`). Expected: two notifications, one each, and never a second one for the same question. Pinned by: Task 2: `the_same_request_id_in_two_conversations_or_two_turns_is_two_questions`, `two_questions_of_one_conversation_notify_twice`, `a_question_notifies_once`.
2. **The user is looking at Faber when the question arrives, then switches to another window.** Expected: no late notification for a question they could already see; a new question does notify. Pinned by: Task 2: `it_never_notifies_while_the_window_is_focused_and_does_not_notify_that_question_later`.
3. **The engine's lists reach the tray out of order, or twice.** Each list is handed over on its own thread, so a list of revision 5 can be handled after revision 6. Expected: the older (or repeated) list changes nothing, the number stays right, and nothing of the ignored list is remembered. Pinned by: Task 2: `an_older_or_repeated_revision_changes_nothing`.
4. **Ten or more questions wait, a conversation has no title yet, or its title looks like a placeholder.** Expected: the badge shows "+", the notification reads "Faber needs you", and a title such as `Use {n} and {title}` is shown as it is, never filled in. Pinned by: Task 3: `the_badge_of_12_is_a_plus_at_16_px`, `the_badge_shows_1_to_9_then_a_plus_and_nothing_for_none`. Task 2: `a_notice_without_a_title_uses_the_name_of_the_app`, `a_title_that_looks_like_a_placeholder_stays_as_it_is`.
5. **A tray picture does not decode, or the badge cannot be drawn on it** (a picture of another size, or a damaged one). Expected: the plain icon stays (and, if the picture itself is the problem, the window icon), with a line on stderr, and the number is still in the tooltip. Pinned by: Task 3: `a_picture_the_badge_cannot_be_drawn_on_is_refused`, `the_shipped_tray_pictures_decode_and_take_a_badge`.

Two more can only be seen on a real tray, so they are in "Hand checks for Erick" at the end: a language change while the window is closed (the notification must come in the new language), and a test run on the maintainer's PC must never pop up a notification.

    use faber_engine::model::{Area, Permission};
    use serde_json::json;

    fn item(conversation: &str, turn: &str, title: &str, requests: &[&str]) -> RunningItem {
        RunningItem {
            conversation_id: conversation.into(),
            turn_id: turn.into(),
            title: title.into(),
            area: Area::Chat,
            project_id: None,
            vendor: None,
            model: None,
            state: if requests.is_empty() { RunState::Working } else { RunState::NeedsYou },
            since: 0,
            permissions: requests.iter().map(|r| Permission { request_id: (*r).into(), tool: "Write".into(), input: json!({}) }).collect(),
        }
    }

    fn the_tooltip_has_the_words_for_each_case() {
        let texts = ShellTexts::default();
        let tip = |running, needs_you| tooltip(&texts, Counts { running, needs_you });
        assert_eq!(tip(0, 0), "Faber");
        assert_eq!(tip(1, 0), "Faber: 1 running");
        assert_eq!(tip(3, 0), "Faber: 3 running");
        assert_eq!(tip(3, 1), "Faber: 3 running, 1 needs you");
        assert_eq!(tip(3, 2), "Faber: 3 running, 2 need you");
        assert_eq!(tip(12, 11), "Faber: 12 running, 11 need you");

    fn the_plural_is_one_for_1_and_other_for_the_rest() {
        let p = Plural { one: "a".into(), other: "b".into() };
        assert_eq!([p.pick(1), p.pick(2), p.pick(11)], ["a", "b", "b"]);
    }

            "needsYou": { "one": ", {n} precisa de você", "other": ", {n} precisam de você" },

        assert_eq!(tooltip(&texts, Counts { running: 2, needs_you: 2 }), "Faber: 2 em andamento, 2 precisam de você");
        assert_eq!(notice_text(&texts, "Relatório"), "Relatório precisa de você");

use faber_engine::model::{RunState, RunningItem};
use serde::Deserialize;
use std::collections::HashSet;

/// A text in two forms, as the screen sends it: `one` for a count of 1 and `other` for any other count. That is what
/// `Intl.PluralRules` picks in all five languages for counts of 1 and more.
#[derive(Debug, Clone, PartialEq, Deserialize)]
pub(super) struct Plural {
    one: String,
    other: String,
}

impl Plural {
    fn pick(&self, n: usize) -> &str {
        if n == 1 { &self.one } else { &self.other }
    }
}

/// The words the shell shows by itself, which the screen sends whenever the language changes. They stay here, so a
/// closed window still has them.
#[derive(Debug, Clone, PartialEq, Deserialize)]
#[serde(rename_all = "camelCase")]
pub(crate) struct ShellTexts {
    pub(super) open: String,
    pub(super) quit: String,
    /// The tooltip while something runs, with `{n}` for the count: "Faber: {n} running".
    running: Plural,
    /// Added to it while something needs the user, with `{n}`: ", {n} needs you".
    needs_you: Plural,
    /// The notification, with `{title}` for the conversation: "{title} needs you".
    notify: String,
}

impl Default for ShellTexts {
    /// English, until the screen has said which language it uses.
    fn default() -> Self {
        let same = |s: &str| Plural { one: s.into(), other: s.into() };
        ShellTexts {
            open: "Open Faber".into(),
            quit: "Quit Faber".into(),
            running: same("Faber: {n} running"),
            needs_you: Plural { one: ", {n} needs you".into(), other: ", {n} need you".into() },
            notify: "{title} needs you".into(),
        }
    }
}

fn fill(template: &str, name: &str, value: &str) -> String {
    template.replace(&format!("{{{name}}}"), value)
}

/// What the tray reports: every item of the running list, and those that wait for the user.
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub(super) struct Counts {
    running: usize,
    pub(super) needs_you: usize,
}

fn counts(items: &[RunningItem]) -> Counts {
    Counts { running: items.len(), needs_you: items.iter().filter(|i| i.state == RunState::NeedsYou).count() }
}

/// "Faber" when nothing runs. Otherwise the count, and the words "needs you" next to it when something does: amber
/// never stands for a number alone [tokens].
pub(super) fn tooltip(texts: &ShellTexts, c: Counts) -> String {
    if c.running == 0 {
        return "Faber".into();
    }
    let mut text = fill(texts.running.pick(c.running), "n", &c.running.to_string());
    if c.needs_you > 0 {
        text.push_str(&fill(texts.needs_you.pick(c.needs_you), "n", &c.needs_you.to_string()));
    }
    text
}

/// A question the user has not answered: the conversation, the turn and the request together, because request ids
/// alone repeat (Codex numbers them from 0 in each server).
type Question = (String, String, String);

/// What the tray remembers between lists, to ignore old ones and to notify once per question.
#[derive(Default)]
pub(super) struct Watch {
    revision: Option<u64>,
    /// The questions of the last list taken in. A question leaves the set when it leaves the list.
    seen: HashSet<Question>,
}

/// What a list changes: the numbers to show, and the title of the conversation of each question to notify.
#[derive(Debug, PartialEq)]
pub(super) struct Update {
    pub(super) counts: Counts,
    pub(super) notices: Vec<String>,
}

impl Watch {
    /// None for a list that is not newer than the last one taken in: it changes nothing. A question the user could
    /// already see (the window was focused when it came) is never notified later.
    pub(super) fn take(&mut self, revision: u64, items: &[RunningItem], window_focused: bool) -> Option<Update> {
        if self.revision.is_some_and(|last| revision <= last) {
            return None;
        }
        self.revision = Some(revision);
        let mut now = HashSet::new();
        let mut notices = Vec::new();
        for item in items {
            for p in &item.permissions {
                let key = (item.conversation_id.clone(), item.turn_id.clone(), p.request_id.clone());
                if !window_focused && !self.seen.contains(&key) {
                    notices.push(item.title.clone());
                }
                now.insert(key);
            }
        }
        self.seen = now;
        Some(Update { counts: counts(items), notices })
    }
}

/// The text of one notification; a conversation without a title yet is called by the app's name.
pub(super) fn notice_text(texts: &ShellTexts, title: &str) -> String {
    fill(&texts.notify, "title", if title.is_empty() { "Faber" } else { title })
}

/// The amber that means "needs you", and the dark ink printed on it [tokens].
const AMBER: [u8; 3] = [0xf2, 0xb1, 0x3c];
const AMBER_INK: [u8; 3] = [0x1d, 0x14, 0x04];

/// The character printed on the badge: 1 to 9, "+" for ten and more, nothing for none.
pub(super) fn glyph(needs_you: usize) -> Option<char> {
    match needs_you {
        0 => None,
        n @ 1..=9 => char::from_digit(n as u32, 10),
        _ => Some('+'),
    }
}

/// The 3 by 5 pixel font of the badge: one row per number, the left pixel in bit 2.
fn glyph_rows(c: char) -> Option<[u8; 5]> {
    Some(match c {
        '1' => [0b010, 0b110, 0b010, 0b010, 0b111],
        '2' => [0b111, 0b001, 0b111, 0b100, 0b111],
        '3' => [0b111, 0b001, 0b111, 0b001, 0b111],
        '4' => [0b101, 0b101, 0b111, 0b001, 0b001],
        '5' => [0b111, 0b100, 0b111, 0b001, 0b111],
        '6' => [0b111, 0b100, 0b111, 0b101, 0b111],
        '7' => [0b111, 0b001, 0b010, 0b010, 0b010],
        '8' => [0b111, 0b101, 0b111, 0b101, 0b111],
        '9' => [0b111, 0b101, 0b111, 0b001, 0b111],
        '+' => [0b000, 0b010, 0b111, 0b010, 0b000],
        _ => return None,
    })
}

/// The tray picture that fits a display scale: the smallest of the three that is not smaller than 16 px times the
/// scale, so a picture is scaled down by the system and never up.
pub(super) fn tray_side(scale: f64) -> u32 {
    if scale.is_nan() || scale <= 1.0 {
        16
    } else if scale <= 1.5 {
        24
    } else {
        32
    }
}

pub(super) fn tray_png(side: u32) -> &'static [u8] {
    match side {
        16 => include_bytes!("../../icons/tray-16.png"),
        24 => include_bytes!("../../icons/tray-24.png"),
        _ => include_bytes!("../../icons/tray-32.png"),
    }
}

/// Source-over of one colour on one RGBA pixel, with `cover` sixteenths of the pixel covered.
fn blend(px: &mut [u8], color: [u8; 3], cover: u32) {
    let (dst_a, back) = (u32::from(px[3]), 16 - cover);
    let total = cover * 255 + dst_a * back;
    if total == 0 {
        return;
    }
    for i in 0..3 {
        px[i] = ((u32::from(color[i]) * cover * 255 + u32::from(px[i]) * dst_a * back + total / 2) / total) as u8;
    }
    px[3] = ((total + 8) / 16) as u8;
}

/// The badge on a square RGBA picture: an amber circle at the bottom right with the character in dark ink. None for
/// a picture it does not know how to draw on (not square, not a tray size, wrong buffer, a character without a glyph),
/// so the caller keeps the plain icon.
pub(super) fn with_badge(rgba: &[u8], width: u32, height: u32, c: char) -> Option<Vec<u8>> {
    // Circle diameter and pixel size of the character. The diameter and the character have the same parity, so the
    // character sits in the middle.
    let (diameter, scale) = match width {
        16 => (9, 1),
        24 => (14, 2),
        32 => (18, 2),
        _ => return None,
    };
    let rows = glyph_rows(c)?;
    if width != height || rgba.len() != (width * height * 4) as usize {
        return None;
    }
    let mut out = rgba.to_vec();
    let side = width;
    // Work in eighths of a pixel: 4 by 4 samples per pixel give the circle a soft edge.
    let (centre, radius) = (i64::from(side * 8 - diameter * 4), i64::from(diameter * 4));
    for y in side - diameter..side {
        for x in side - diameter..side {
            let mut cover = 0;
            for sy in 0..4 {
                for sx in 0..4 {
                    let (dx, dy) = (i64::from(x * 8 + sx * 2 + 1) - centre, i64::from(y * 8 + sy * 2 + 1) - centre);
                    cover += u32::from(dx * dx + dy * dy <= radius * radius);
                }
            }
            if cover > 0 {
                let at = ((y * side + x) * 4) as usize;
                blend(&mut out[at..at + 4], AMBER, cover);
            }
        }
    }
    let (left, top) = (side - diameter + (diameter - 3 * scale) / 2, side - diameter + (diameter - 5 * scale) / 2);
    for (row, bits) in rows.iter().enumerate() {
        for col in 0..3u32 {
            if bits >> (2 - col) & 1 == 1 {
                for dy in 0..scale {
                    for dx in 0..scale {
                        let (x, y) = (left + col * scale + dx, top + row as u32 * scale + dy);
                        let at = ((y * side + x) * 4) as usize;
                        out[at..at + 3].copy_from_slice(&AMBER_INK);
                        out[at + 3] = 255;
                    }
                }
            }
        }
    }
    Some(out)
}

//! question. What to show and when to notify is decided by plain functions (tested without a tray); the rest hands
//! those answers to Tauri. The deciding lives in `decide`, the drawing in `badge`.

/// The tray's state. Managed by Tauri from the start of `setup`, so the engine's first event finds it.
#[derive(Default)]
pub(crate) struct Tray(Mutex<State>);

fn lock(tray: &Tray) -> std::sync::MutexGuard<'_, State> {
    tray.0.lock().unwrap_or_else(|e| e.into_inner())
}

/// The picture for `needs_you` waiting items at this display's scale. A tray picture that does not decode falls back
/// to the window icon; a badge that cannot be drawn leaves the plain picture.
fn picture(app: &AppHandle, needs_you: usize) -> Option<Image<'static>> {
    // Read at each update, so a display scale that changes while nothing else does is picked up at the next update.
    let scale = app.primary_monitor().ok().flatten().map_or(1.0, |m| m.scale_factor());
    let side = tray_side(scale);
    let plain = match Image::from_bytes(tray_png(side)) {
        Ok(image) => image,
        Err(e) => {
            eprintln!("faber: tray-{side}.png did not decode ({e}); using the window icon");
            return app.default_window_icon().map(|i| i.clone().to_owned());
        }
    };
    let Some(c) = glyph(needs_you) else { return Some(plain) };
    match with_badge(plain.rgba(), plain.width(), plain.height(), c) {
        Some(rgba) => Some(Image::new_owned(rgba, plain.width(), plain.height())),
        None => {
            eprintln!("faber: no badge could be drawn on tray-{side}.png; showing the plain icon");
            Some(plain)
        }
    }
}

/// Puts the tooltip and the picture of the current counts on the tray.
fn show_counts(app: &AppHandle, s: &State) {
    let Some(icon) = &s.icon else { return };
    if let Err(e) = icon.set_tooltip(Some(tooltip(&s.texts, s.counts))) {
        eprintln!("faber: the tray tooltip could not change ({e})");
    }
    if let Some(image) = picture(app, s.counts.needs_you)
        && let Err(e) = icon.set_icon(Some(image))
    {
        eprintln!("faber: the tray icon could not change ({e})");
    }
}

pub(crate) fn create(app: &tauri::App) -> tauri::Result<()> {
    let handle = app.handle();
    let tray = handle.state::<Tray>();
    let mut s = lock(&tray);
    let open = MenuItem::with_id(app, "open", &s.texts.open, true, None::<&str>)?;
    let quit = MenuItem::with_id(app, "quit", &s.texts.quit, true, None::<&str>)?;
    let mut builder = TrayIconBuilder::new()
        .tooltip(tooltip(&s.texts, s.counts))
        .menu(&Menu::with_items(app, &[&open, &quit])?)
        .show_menu_on_left_click(false)
        .on_menu_event(|app, e| match e.id().as_ref() {
            "open" => crate::show(app),
            "quit" => app.exit(0),
            _ => {}
        })
        .on_tray_icon_event(|tray, e| {
            if let TrayIconEvent::Click { button: MouseButton::Left, button_state: MouseButtonState::Up, .. } = e {
                crate::show(tray.app_handle());
            }
        });
    if let Some(image) = picture(handle, 0) {
        builder = builder.icon(image);
    }
    s.icon = Some(builder.build(app)?);
    s.menu = Some([open, quit]);
    Ok(())
}

/// The screen's words for the menu, the tooltip and the notification. A language change reaches the tray at once.
pub(crate) fn set_texts(app: &AppHandle, texts: ShellTexts) -> Result<(), String> {

    if let Some([open, quit]) = &s.menu {

        quit.set_text(&s.texts.quit).map_err(|e| e.to_string())?;
    }

        icon.set_tooltip(Some(tooltip(&s.texts, s.counts))).map_err(|e| e.to_string())?;
    }

}

/// A new running list from the engine. Lists can arrive out of order (each runs on its own thread), so the newest
/// revision wins.
pub(crate) fn on_running(app: &AppHandle, revision: u64, items: &[RunningItem]) {
    let tray = app.state::<Tray>();
    let mut s = lock(&tray);
    if s.icon.is_none() {
        return;
    }
    // A closed window is not focused either.
    let focused = crate::main_window(app).is_some_and(|w| w.is_focused().unwrap_or(false));
    let Some(update) = s.watch.take(revision, items, focused) else { return };
    if update.counts != s.counts {
        s.counts = update.counts;
        show_counts(app, &s);
    }
    for title in &update.notices {
        // Faber does not rely on the user clicking a notification, which each system handles in its own way.
        if let Err(e) = app.notification().builder().title(notice_text(&s.texts, title)).show() {
            eprintln!("faber: the notification could not be sent ({e})");
        }
    }
}

## Deviations from spec

Where this plan differs from the spec, and why. Nothing here changes what the spec asks the tray to show or when to notify, except where it says so.

1. **`tray.rs` is three files.** The spec names one new file, `src-tauri/src/tray.rs`, and its tests "in `tray.rs`". The code is split by what it decides: `tray/decide.rs` (the words and "is this question new") and `tray/badge.rs` (the pixels) are plain functions with their own tests; `tray.rs` is the glue to Tauri. Each can be read, and each task can be reviewed, on its own.
2. **Three more files change than the spec lists.** `ui/i18n.ts` gets `templates` (the screen must send the words with `{n}` and `{title}` still in them, and `t()` always fills them). `tests/ui/i18n.check.ts` gets one check that pins that, in all five languages. `docs/design.md` step 4 of "App icons" said "until B6, the tray uses the window icon", which is no longer true.
3. **The tray gets the engine's lists on a thread of its own** (`tauri::async_runtime::spawn_blocking`), not inside the emit closure. The spec says the closure "also passes `Running` events to `tray.rs`". The closure runs with the engine's lock held, and tray calls (the icon, the tooltip, `is_focused`) wait for the main thread, which can be waiting for that lock (`show` builds the window, which reads the engine's settings). The spec's own rule, "keeps the highest revision it has seen and ignores older lists", is what makes the thread order harmless.
4. **The tray's state is its own managed state** (`tray::Tray`), created at the start of `setup`, instead of a field of `Faber`. The `tray` field of `Faber` and `create_tray` in `main.rs` are removed.
5. **A question that arrives while the window is focused is never notified later.** The spec says "only while the main window is unfocused or closed" and is silent on a question that was already waiting when the window lost focus. The user could see it when it came, so a late notification would repeat what they already know. A new question does notify.
6. **A conversation with no title yet is called "Faber" in the notification** ("Faber needs you"). The engine sends an empty title until the conversation has one, and the spec's template needs a title. The notification has a title and no body.
7. **The shape of the badge is the AI's choice** (the spec says only "an amber circle at the bottom right, with the digit or +, in a small built-in pixel font"): the circle is 9, 14 and 18 px wide on the 16, 24 and 32 px pictures, flush with the bottom right corner, with a soft edge (4 by 4 samples per pixel); the characters are 3 by 5 px, drawn twice as large on the 24 and 32 px pictures. The picture is picked by display scale as "the smallest of the three that is not smaller than 16 px times the scale" (so 125% and 150% use 24 px, 175% and above use 32 px). The display scale is read from the primary monitor at each update, not watched, so a scale that changes while nothing else does is picked up at the next update.
8. **The tooltip words are two plural keys with the separator inside** (`tray.running` is "Faber: {n} running", `tray.needsYou` is ", {n} needs you" or ", {n} need you"), so a language can change the separator or the grammar. English says "need" for 2 or more; the spec writes the singular only.
9. **A failed notification, in any system, is only logged on stderr.** The spec names macOS permission. On desktop, `tauri-plugin-notification` reports permission as always granted and fails inside `show()` when the system refuses, so one `eprintln!` covers every case and the badge stays. Review round (cross-vendor): the plugin only reports a notification it cannot build, because it sends in the background and drops the system's answer, so a refused delivery leaves no line; the ceiling is noted in `tray.rs`, and the way out is `notify-rust` (already in `Cargo.lock`) if a hand check shows a silent failure. A question notifies once ever (the set of seen keys is never pruned), the tray picture is redrawn when the display scale changes with the counts unchanged, and on Linux, whose backend cannot show a tooltip, a disabled first menu item repeats the tooltip text. The English defaults in `ShellTexts` stay: the screen's effect sends the real words on mount, before any run can exist, so they only cover a window that never loads.
10. **`Cargo.lock` gains** `tauri-plugin-notification`, `tauri-winrt-notification`, `notify-rust`, `mac-notification-sys` (macOS only), `image`, `moxcms`, `pxfm`, `byteorder-lite` (the `image-png` feature of `tauri`), and `rand`, `rand_chacha`, `rand_core`, `ppv-lite86`, `zerocopy`, `zerocopy-derive` (newer versions pulled in next to the old ones). `cargo` writes it; nobody edits it by hand.
