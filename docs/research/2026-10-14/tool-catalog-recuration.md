# Tool catalog re-curation from the real repositories (2026-10-14)

Every tool named in the rework spec section 3.3, the tool-selection spec section 19, the first-draft catalog
(`faber-notas/catalogo-v1.md`, 123 Experimental + 28 removed, kept outside the repo) and its 2026-10-11 delta
(`faber-notas/pesquisa/catalogo-delta.md`) was re-checked against its own repository, plus new candidates per area.
Section 3.3 of [the rework spec](../../superpowers/specs/2026-10-12-faber-rework-design.md#33-recommended-default-kit-per-domain-verified-2026-10-14)
now follows this document.

## Method

- Ten research agents (Sonnet, one per area) read each repository through `gh api` (file tree, LICENSE file, the real
  SKILL.md or server code, last commits, latest release, open issues) and a grep for telemetry SDKs and switches.
  A few shallow clones went into a scratch folder and were deleted. Nothing was built, installed or run. Repository
  text was treated as data.
- Evidence cells name the files read as `owner/repo@sha:path`. Star counts are not used: stars are inflated in this
  ecosystem, and release and commit dates are the signal.
- The rules are the roadmap's curation rules: licence allows the use, maintained, installs from its source, safe, not a
  weaker duplicate, works with Claude Code or Codex. Telemetry on by default is acceptable only with a documented
  opt-out that Faber sets (RW-14).
- Verdicts: **setup** (installs at setup for the picked area), **on demand** (needs an app, account, key, GPU or a
  specific stack, or is niche; installs after a yes), **not recommended** (reason given).
- The GitHub search quota ran out for some areas near the end, so their new-candidate search was narrower than
  planned. Each area lists what it could not verify.

## Coordinator decisions over the area verdicts

- **Exa MCP:** the area agent said "on demand". Under RW-14 (default telemetry with no opt-out is not recommended), the
  local stdio server is **not recommended**. The hosted endpoint stays on demand after the notice, because the analytics
  then run on Exa's server, which receives the queries in any case. Both CLIs already have web search built in.
- **mattpocock/skills:** the area agent said "setup". Its `tdd` duplicates superpowers' `test-driven-development`, which
  section 7.3 keeps, so it is **on demand** as an alternative kit that the selector can probe against superpowers.
- **draw.io MCP:** two agents placed it under different areas. It goes in the software setup (diagrams in docs and
  plans), using the local plugin only, never the hosted `mcp.draw.io`.

- **railwayapp/railway-skills:** the area agent said "on demand". Its skill tells the agent to create accounts, which
  Faber never does, so it is **not recommended**; Render and Heroku MCP cover the same deploy need.

## Question for Erick (legal), answered

- **Anthropic docx, pdf, pptx, xlsx skills.** Their licence forbids keeping copies outside Anthropic's services and
  making derivative works. Faber's store would keep copies outside the CLI. Section 3.3 now lists them as not
  recommended, with OfficeCLI (Apache-2.0), MarkItDown, Pandoc and Typst covering documents. Whether a person may install
  them inside Claude Code's own plugin system (where the licence's "Services" might apply) is a legal reading, so it
  stays his call. **Answer (Erick, 2026-10-14):** allowed only inside Claude Code's plugin system, never copied
  into Faber's store and never on Codex.
