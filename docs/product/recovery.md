# Recovery across desktop shells

Windows migration, manual rollback and engine-process recovery. The overall shell architecture is in [architecture.md](architecture.md).

## Going back to the Tauri build

On Windows, the Electron installer saves the old executable as `previous/faber-tauri.exe` in the installation folder. Close Faber and disconnect the internet before running it, or reinstall a known Tauri installer while offline. Reconnecting may update Faber to Electron again. The executable alone may need files from that installer; recovery has not been proven on a real installation. Do not uninstall Electron before saving this copy elsewhere.

After it starts, Electron saves conversations, child transcripts, project attachments, side chats, Chat group files, legacy `chat/` work and top-level JSON files in `backup-before-electron-<uuid>` under the data folder (normally `%APPDATA%/Faber`, or `FABER_DATA_DIR`). The current sibling `<data-folder>-chat-work/` is saved under the backup's `chat-work/`. It leaves the webview profile, caches and logs out. The backup runs asynchronously and is limited to 10,000 files and 2 GiB across both roots; links are refused. If it exceeds a limit, there is less than twice the needed space, or copying fails, startup continues and `update.log` records it; the next start retries, so a delayed backup may contain data already changed by Electron. To restore, close Faber, copy `chat-work/` back to the sibling `<data-folder>-chat-work/`, and copy the other saved entries back into the data folder. Changes made after the backup will be replaced, so save the current data separately first. Compatibility with newer data is not guaranteed. Two starts that never reached Electron's ready event are recorded in `update.log`; this does not automatically roll back.

Electron imports Windows Tauri drafts before starting the screen: an isolated copy of Faber's Chromium storage is read at `http://tauri.localhost`, then unsent text and attachment Blobs are committed at `faber://app`. Existing Electron drafts and deletion intents win. The original profile is never modified. The browser marker `faber.tauri-drafts-imported` prevents repeat imports; per-field progress survives consumption so a partially failed migration cannot resurrect an already used draft. Failed field publication rolls back text and attachment markers; failures retry at the next start. Screen text and attachment writes first resolve their field, even when the import loop never reached it, so sending or clearing newer work cannot restore an old draft; failed progress writes keep the existing failed-save protection. Empty initial composer hydration resolves no import: a failed legacy field remains retryable until new text or actual consumption replaces it. This does not read the native WebKit storage used on macOS or Linux. Temporary `draft-profile-import/` copies may remain locked until exit and are removed on the next start. The forced-close storage flush is separate (PR #661).

Normal Quit closes the host's input and waits for its own exit, with a 60-second bound for a hung host. An unexpected host exit rejects pending requests and restarts it with backoff from 1 to 30 seconds; after a fresh state reply the existing event channel refreshes state and the open conversation in place. The renderer is retained, so newer in-memory drafts and failed-write protection survive even when storage remains unavailable; running and background revisions reset for the replacement engine. A state reply alone does not reset backoff: the host must stay up for 30 seconds first. Requests are never replayed. A normal Quit cancels recovery.
